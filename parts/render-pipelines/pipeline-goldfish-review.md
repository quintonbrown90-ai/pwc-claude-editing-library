# RENDER PIPELINES — elephant / goldfish / drift report (@nishantchahar.ai, Tier S)

Source: @nishantchahar.ai reel DfeAqJwDxeT (goldfish reviews the plan, Nov 2026)
— INFERRED reconstruction; the plugin itself is third-party code, NOT
downloaded, NOT scanned — a scan would be needed before any fold-in (SAFETY.md
§6). The discipline is the steal, not the plugin.

## The rule
Three roles, in order. ELEPHANT = Claude with full context writes the edit plan
(storyboard) section by section. GOLDFISH = a fresh reviewer (a second Claude
pass with ZERO context) reads ONLY the plan + the export and tears it apart for
gaps. NOTHING renders until Q approves the plan. DRIFT REPORT = after the
render, a check that the export still matches the approved plan. "You can't
spot your own blind spots but fresh eyes catch them right away."

## Executable steps
1. **Elephant plan:** Claude (full context: script, brand kit, style rules)
   writes the storyboard section by section — line → visual → device → sound.
2. **Goldfish review:** a fresh pass with no context reads ONLY the plan and
   the export. It lists gaps: lines with no visual, devices with no trigger,
   claims with no proof on screen. It may not praise; it finds holes.
3. **Gate:** nothing renders until the plan is approved (Q's storyboard gate +
   pilot gate). The goldfish's gaps are fixed in the PLAN, not in the render.
4. **Drift report:** after the render, section-by-section check — ✓ matches /
   ! drifted — against the approved plan. The report is the QC record: every
   drift names its section, timestamp, and fix.
5. **Why it works:** this is Q's existing discipline formalized — Muse QCs
   every video Claude makes (Q, Nov 7). The goldfish is Muse's independent QC
   with a name and a format.

## Worked example (PWC)
P-pack edit: elephant storyboards the proof wall → goldfish reads only the
board + export and flags "tile 11 vanishes at 0:54 when he says 'a tile like
this'" → fixed in the plan → drift report after render: 12/12 sections match.

## Human-made check
The drift report is written on the exported file, in motion — never from the
builder's say-so.
