# RENDER-PIPELINES — beat table + contact sheet: plan first, then stills, wait for OK (@growwithalex, Tier S)

Source: Grow with Alex — "Claude Opus now EDITS my Videos for Social Media"
(https://www.youtube.com/watch?v=oTJGDMKAbH4). INFERRED reconstruction from the
visible workflow; no files downloaded. Knowledge entries V8-144, V8-145,
V8-146, V8-147, V8-148. Corroborated by V8-17 (plan before build), V8-41
(animation plan as a table), V8-50 (beat map), V8-114 (planning document),

## The rule
No render before the plan is approved. Beat table first (the written plan),
contact sheet second (one still per moment, all on one page), human OK third,
render last. A boring video spotted on the contact sheet costs nothing; a
boring render costs the whole run.

## Executable steps
1. **Beat table** — every moment in one table: timing, what's on screen, one
   sentence per beat. The table IS the video before it exists.
2. **Contact sheet** — one still per moment, all on one page. See the whole
   video as a picture before it renders. If the sheet is boring, the video
   will be boring — fix the sheet.
3. **Seven rules in every brief** (three spoken): sound-off clear in 2
   seconds; every scene proves its line; the biggest point is the biggest
   thing on the screen. The rules are the brief's spine; the rest is format
   + reference + source + assets.
4. **Brief must name format + duration + resolution** so Claude doesn't
   guess: 16:9 / 3:4 / 9:16, 25s, 1920×1080. Reference = movement only, not
   style ("break the reference down into its moves"). Source = website /
   branding doc. Assets = Drive/Dropbox folder, full-res from the start.
5. **Transcribe first, then lock the script; plan the ending in the brief.**
   Motion only where it proves the line — motion everywhere is noise, and
   "motion" gets misread as "movement": disambiguate with a movement
   reference in prompt one, not after a flat v1.
6. **Second-chat editor feedback.** Keep a second "editor's chat" for precise
   feedback prompts — clear, concise, no waffling — and have Claude report
   which rules it bends so you can preempt them. That's how prompts stay
   minimal.
7. **Watch every version on your phone** the way the audience will. A plan
   that reads well on desktop and fails on phone is a failed plan.

## Worked example (PWC)
Q's P1 proof video: beat table (hook 0–2s → wall builds → tile pulses gold →
CTA) → contact sheet (one still per beat, wall behind Q, face clear) → Q/Muse
OK → render. The wall tile that vanishes at 54s would have shown as a gap
on the sheet. Keyword WAITLIST.

## Human-made check
The contact sheet is reviewed still-by-still: every beat earns its place,
nothing sits over Q's face, the biggest point is the biggest thing on screen.

## PWC skin
Beat tables and contact sheets carry the PWC palette (teal #14A886 + gold
#FEE238 on navy #00214E). NO RED. Stills never crop Q's face; the face stays
whole in every frame of the sheet.
