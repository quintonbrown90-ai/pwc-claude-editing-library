## The rule
Claude is the coordinator, not the whole team. Seven jobs, each a named tool:
editor / transcriber / animator / researcher / screen-editor / sound-designer /
finisher. Name the job before picking the tool — a job with no name gets done
by whoever shouts loudest, which is how renders go wrong.

## Executable steps
1. **Seven jobs (editor / transcriber / animator / researcher /
   screen-editor / sound-designer / finisher).** Each job is a named tool;
   Claude coordinates. The five-role short-form team is the same shape at
   smaller scale: researcher / editor / designer / copywriter / manager —
   researcher reads the whole transcript and picks the strongest hooks,
   editor cuts, designer multiplies, copywriter captions, manager queues.
2. **Transcriber: Parakeet (NVIDIA, free).** Local, free, timestamped
   transcription — an alternative to Whisper for the pre-clean stack. Test
   Parakeet vs faster-whisper base on Q's footage for accuracy + speed
   before adopting.
3. **Researcher-as-B-roll: the exact post/page as proof on screen.** Claude
   browses, grabs the original X post or web page, highlights lines, zooms
   into sections. "The proof shows up on screen" — real sources, never
   recreations. Maps directly onto Q's proof-on-screen rule.
4. **The AI editor kit: ElevenLabs = ears, HyperFrames = designer, watch
   skill = eyes, FFmpeg = hands.** Plain Claude Code without them "spits out
   a shitty video" — the tools are the training of the junior editor.
5. **Video Editor workspace folder.** Raw footage, B-roll, music, sound
   effects, inspiration, projects, exports. Catalog music by mood — Claude
   tracks BPM and energy and picks the right audio per video. Footage can
   live on an external drive; just tell Claude where it is.
6. **FFmpeg as finisher: automated QC before the human sees the video.** Cut
   black screens, check audio sync — a machine pass that runs before any
   human review. Automate the finisher pass, keep the human pass for taste.
7. **Skill = 1,400 lines, built by Claude, 36 rules; every note becomes a
   rule.** Same doctrine as the self-improving skill and the v6 kingketo
   finding (every note becomes a rule, 35 rules and counting). The skill file
   is the accumulating record. Timestamped feedback, then "add it to the
   skill" — two steps, not one. A fix without the save is a fix you will pay
   for again.
8. **Sub-agent edit + main-agent QA.** "Edit this video" spawns a sub-agent
   to edit the entire video; after it's edited it passes back to the main
   agent for quality assurance. The edit and the QA are different agents.
9. **Designer makes 3 versions per edit.** The edit itself; a before/after
   split (raw one side, edit the other); one with an editing-timeline
   animation. One edit becomes three posts — the multiplication step.
10. **Eye-tracking cuts + real screenshots pulled automatically.** Looking at
    camera = full screen; looking at the board = bottom corner; looking at a
    script = cut it out. When you say a number or a thing, Claude pulls the
    real screenshot (client results folder, calendar UI) onto the screen.

## Worked example (PWC)
Q's week: researcher pulls the week's proof posts (real screenshots) →
transcriber (Parakeet) timestamps Q's takes → editor cuts → animator builds
plates → sound-designer places SFX → finisher runs the FFmpeg QC pass →
main-agent QA watches whole → designer multiplies the winner into 3 versions
(edit / before-after / timeline). Every note becomes a rule in the skill.
Keyword WAITLIST.

## Human-made check
The org chart is a checklist, not a poster: every job has an owner and a
done-state before the video moves on. The finisher pass runs, then a human
watches the whole video — the machine pass never replaces the watch.
