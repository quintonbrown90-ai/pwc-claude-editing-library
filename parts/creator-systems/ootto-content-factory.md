# CREATOR SYSTEMS — Ootto Content Factory chain

Source: Ootto-AI/claude-content-skills repo (MIT) —
`skills/content-factory/` in `uploads/QUARANTINE/ootto-content-skills/`

## The rule
One command runs the chain in order — format → reel → captions → DM loop.
The chain is the product: the user gives one command, the factory does the
rest, in order, no skipping.

## Executable steps
1. The chain (4 jobs, in order, each a skill): (a) FORMAT — find a proven
   format from the mined library (the hook-mining part's output); (b) REEL
   — build the reel from the format + Q's script (the analyzer's output is
   the brief); (c) CAPTIONS — write the SEO caption (≤500 chars, keyword
   CTA + dual-CTA profile line, per Q's caption law); (d) LOOP — the
   comment-to-DM flow (ManyChat, value first, then WAITLIST capture — Q's
   flow, not Jayant's auto-DM).
2. The chain runs in order and stops on failure: if the format is not in the
   library, the chain stops and asks (it does not invent a format). If the
   hook fails the doctor (the virality part), the chain stops before the
   reel.
3. The output is filed in the one-stack (date / title / keyword — file,
   cover, caption) — the factory's output goes straight into the stack,
   never into the chat as a loose file.

## Worked example (PWC)
One command "factory: WAITLIST proof reel" → format: proof-led open (from
the library) → reel: P-pack talking head + proof full-screen in first 2s →
caption: ≤500 chars, Comment WAITLIST + profile line → flow: WAITLIST
capture verified live before posting. Keyword WAITLIST.

## Human-made check
The factory is a chain of skills, not a person — a human (Muse) still
watches the whole video before delivery (Q's QC rule: never ship on a
builder's say-so).
