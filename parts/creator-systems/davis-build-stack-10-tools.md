## The rule
"Design to deploy, in the order a build happens. One job each. Where
two tools fit, which one and when."

## Executable steps (the stack, in his order)
1. **01 DESIGN — Claude Design · Framer:** "Describe a layout, desk,
   or mockup and get an editable design back" (Claude Design); "Visual
   website builder. CMS, animations, and hosting built in, so the site
   publishes from the canvas" (Framer).
2. **02 SOURCE CONTROL — GitHub:** "Where your code lives. Every
   change is saved, so you can see what changed and roll back." Cloud
   backup / tests run on every change / track bugs and to-dos / full
   history: undo any change. (GitHub is already authorized for Q as
   quintonbrown90-ai — no new connection here.)
3. **03 FRAMEWORK — Next.js:** "A web framework. Pages, logins, and
   the backend code that talks to your database live in one project."
   Pages from folders / fast first load / backend built in.
4. **03 CODE — Claude Code · Codex:** "Build with it, or hand it
   off." BUILDS WITH YOU — Claude Code: "AI coding agent that works
   in your project with you. Reads your files, runs commands, builds
   step by step." WORKS FOR YOU — Codex: "Hand it a list of tasks, it
   works them in parallel in the cloud and sends back finished changes
   to review." The builds-with-you vs works-for-you split is the
   pick: one tool per job, chosen by how the work is handed over.
5. **05 AUTOMATION — n8n:** "Connect your apps. Automate the rest."
   "A visual automation builder. Chain apps and AI steps into
   workflows that run on a trigger or schedule. Self-host it or use
   their cloud."
6. **07 DEPLOY — Cloudflare:** "Where the app goes live. Your code,
   files, database, and domain run from one account, on servers close
   to every user."
7. **DATABASE — Supabase · Neon:** "Your app's database plus logins,
   file uploads, and live updates, in one dashboard." Neon: "just the
   database. Costs nothing when idle, and copies in a click to test
   changes safely."
8. **08 DECISIONS — Jev:** "A decision model for agents. Give it text
   and options; it picks one and says how sure it is. Use it to route,
   score, or approve steps." "Under a second, per decision / A choice,
   not an essay." Jev is a third-party product (operatorus.ai) — named
   only, not adopted.
9. **09 MEMORY — Obsidian · Mem0:** "Persistent memory that compounds."
   "Notes your agent writes and you can read" (Obsidian) / "Memory for
   apps where each user needs their own" (Mem0). (See the Operator OS
   vault part for the .md-folder doctrine — same memory, two lenses.)
10. **10 INTEGRATIONS — MCP · Composio:** "How your agent connects to
    Gmail, Slack, and GitHub." MCP: "The standard way to plug an app
    into an AI agent. One connector per app." Composio: "One account,
    hundreds of apps, logins handled for you." FLAG: Composio's
    "logins handled for you" is a credential flag — a third-party
    service holding logins; named only, NOT adopted, NOT connected.
    MCP servers generally: scan before folding in, never install
    unvetted (SAFETY.md §6/§9).
