Source: @gregisenberg reel DWcIFs7EVIh (PUBLISHED, spoken verbatim).

## The rule
"Why would you subscribe to Claude only to use 10% of its brain?
Here's a setup that makes it worth the buy." Four files, and Claude
references them every time before it does anything.

## Executable steps
1. **AGENTS.md — the onboarding doc:** "Start by creating the
   agents.md file. It's what you would first give an employee while
   onboarding them. Your business, voice, and how you like to work.
   Claude references that every time before it does anything." The
   file is the first thing a new hire gets — so it is the first thing
   Claude gets. Q's AGENTS.md is exactly this: how the work runs here,
   the conventions, the lessons learned the hard way.
2. **The context folder:** "heavier and more nuanced information" —
   the files that don't fit in the onboarding doc but that Claude
   needs to read before it works. "Feeding context alone isn't
   enough" — context without memory repeats the same mistakes.
3. **MEMORY.md:** "It also needs to remember your preferences" — what
   was decided, what was ruled out, what Q already said no to. Memory
   is the file that stops the same correction being given twice.
4. **The skills folder:** the reusable workflows, one per file. "Walk
   through a process once and it packages all of it into a reusable
   workflow" — do it once by hand, package it as a skill, reuse it
   forever. (Same doctrine as the library's own save-it-as-a-skill
   part — one doctrine, this is its setup-shaped instance.) His
   result claim: a 4-hour task becomes a single instruction — his
   figure, recorded as his.

## Worked example (PWC)
Muse runs on exactly these four files: AGENTS.md (how work runs here),
the context folder (USER.md, SOUL.md, MEMORY.md, the people/groups
indexes), MEMORY.md (durable facts: the Dec 7 cohort, the $97/mo
Premium-only tier, the blur law, the newest-version rule), and the
skills folder (this library — 197 parts and counting). A new worker
reads the four files and knows the operation; a new Claude session
does the same. Keyword WAITLIST.

Claude never writes its own onboarding. If AGENTS.md says it, it holds;
if it doesn't say it, Claude asks.
