## The rule
Trial reels are a test bed, not a dumping ground. Rebuild the master first,
then vary it on purpose: five intentional tests, each with a metric. A
variation is a new opening + new graphics + new structure — zoom 1.02%, flip,
or one hook-line swap no longer counts and Instagram flags it as a duplicate.

## Executable steps
1. **Master file + master prompt.** Drive folder + prompt → beats → permission
   → assets → cheat sheet + brand color pack → output close to the original.
   Master prompt locks everything: full project saves, Drive project, notes
   saved after every round, project memory before any versions. Variations
   shown as master + variation side by side, 10s max — never the full reel
   per test (saves credits/time).
2. **Five intentional trial tests, each with a metric.** Straight In (cut
   3.5s sooner to payoff; skip rate); Micro (lines 3–8 only, 13s vs 41s,
   loop on red; watch time + sends); Halo (motion around the face in the
   first seconds; skip rate); Breakdown (freeze on the red post, point at
   things, sound-off spelling; skip rate + % watched); Paint Pause (B&W
   open, paint floods red; skip rate + watch time). Five is enough — be
   intentional about why you're making each one.
3. **Duplicate rule.** A new opening + new graphics + new structure. What
   counts as "new" is the opening, the graphics, and the structure — not a
   filter or a flip.
4. **Run rules.** Max 5 trials/day, not every day; compare trials to trials,
   never to normal reels; winner pushed within 48h. Winner thresholds: 5+
   points of skip rate, 1.5× per-1k. Changed opening → skip rate; changed
   length/pace → % watched / watch time; changed ending → saves / sends /
   comments / leads.
5. **Scheduling safety rules.** Max 6/day, min 30 min between posts, never
   the same image or audio on the same day. Built-in rules so Instagram
   stays safe and the trial-reels feature isn't lost to spamming.
6. **/viral-reels recreation pipeline.** Paste a URL → same length, same
   hook, same audio, your B-roll. Download the original → extract audio →
   length → visual hook → adjust the hook to your style → find matching
   B-roll of you → piece it together in the exact same length with the exact
   same hook and audio → schedule on trial reels → analyze performance.
   Approval gates + tracker: ask for text approval, make three versions
   from three B-roll images, save everything into a tracker.
7. **Three variations per reel (the uniqueness spec).** Different hook,
   music, color, brightness/contrast, one flipped — everything changes so
   each variation is genuinely unique content, not the same video reposted.
   Trial reels as a free testing playground: only non-followers see them;
   winners go to the main feed, losers stay trial reels forever.
8. **Schedule + ManyChat auto-trigger.** "Schedule three reels" → next free
   slot → automatically creates the comment trigger for the promised keyword
   in ManyChat. The scheduling step wires the funnel. (ManyChat routing must
   carry the live waitlist capture — the keyword flow is verified before the
   trial ships, per the queued-posting integrity rule.)

## Worked example (PWC)
Q's proof reel: master rebuilt from the posted P1 file → five intentional
trials (Straight In cuts 3.5s sooner; Micro is lines 3–8 only; Halo adds
motion around the face; Breakdown freezes on the payout post; Paint Pause
opens B&W) → winner by skip rate + watch time → pushed to main feed within
48h, loser trials stay trial-only. Keyword WAITLIST.

## Human-made check
Every trial variation is a real test with a named metric and a decision
attached. No variation ships without its opening, graphics, and structure
all changed — and no winner is pushed without Muse verifying it live.
