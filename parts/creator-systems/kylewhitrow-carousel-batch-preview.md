# CREATOR-SYSTEMS — batch carousels: generate the set, preview the grid, fix the set (DRAFT — v9 bulk-b)

Source: @kylewhitrow "I just created 26 carousels using Claude Code" (DY2OL6zFP5E) + the 53-image hook-slide run (DYzpaOZgsAB). INFERRED reconstruction from the visible transcript; his setup is not in the harvest.

## The rule
Generate ALL carousels first, then review the SET — never one carousel at a time, never blind. Batch generation, grid preview, two-level notes, one paste of feedback.

## Executable steps (PWC)
1. **Generate the batch:** all carousels (his run: 26) in one run, from the briefs. Same for images: his 53 hook slides in one run (OpenAI Image 2, API-connected — the generation route is his; Q's slides use the PWC design system, teal/gold on navy, real creator examples, never stock).
2. **Preview grid:** render a preview HTML / grid with every carousel (and every slide) visible at once. The grid is the review surface — the same device as the 53-hook grid (all 53 hooks visible at once).
3. **Two-level notes:** feedback is scoped per carousel OR per slide — never a vague "fix it." Whole-carousel notes ("this carousel's hook is weak") and single-slide notes ("slide 4, the number is wrong") are different granularities and travel separately.
4. **Copy-all-feedback:** one paste carries every note — no per-slide round trips. Claude fixes the set, re-renders the preview, repeat until thumbs-up.
5. **Thumbs-up or notes:** every carousel ends in one of two states — approved, or notes. No third state, no silent pass.

## PWC skin
Carousels follow the Sky carousel system (teal #14A886 + gold #FEE238 on navy #00214E, no red) and the Q carousel rules (real creator examples, never Q himself in illustrations). "The text is clean" is the pass/fail for generated slides — text legibility first; a slide with unreadable text fails even if the art is good. Q's designed thumbnails stay human-designed; generated slides are drafts until the preview grid passes.
