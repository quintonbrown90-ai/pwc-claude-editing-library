## The rule
Batch work is a LOOP, not a straight line: preview HTML → feedback →
rebuild. Three machines:
1. 26-carousel batch: one preview HTML renders all 26 covers; feedback is
   given against the preview (not the files), then one rebuild pass.
2. Logo animation skill: 10 logo animations in 30s — the logo is a SKILL
   (pick the animation, don't re-animate it each time). PWC logo in every
   video (brand law) — the skill is how it stays fresh without re-work.
3. Batch CTA swap: one copy JSON + one preview HTML swaps the CTA across
   53 videos at once. The keyword CTA is DATA, not baked pixels — change
   the JSON, re-render the batch, verify the preview.

## Executable steps
1. Build the preview HTML first (covers / frames / CTA states in one page).
2. Feedback round uses the preview only — "slide 7's hook is weak" beats
   "re-render everything and I'll look".
3. Logo: pick from the 10-animation library; logo outro ≤1s after the last
   word (dead-air gate).
4. CTA swap: edit the copy JSON (keyword + line), re-render, verify every
   video's CTA in the preview before any post.
5. Keyword flows live before posting — a swapped CTA with no flow is a
   dead end (ENGINE Step-0 gate).

## Worked example (PWC)
YAP30 pack (90 posts): one preview HTML of all 90 covers; Q marks 6 weak
hooks on the preview; one rebuild pass fixes them; the CTA JSON flips all
90 from WAITLIST to CALENDAR where the lane calls for it — verified in the
preview, then posted.
