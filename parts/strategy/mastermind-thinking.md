# MASTERMIND THINKING — how the mastermind reasons before it builds

**Owner:** The Master (orchestrator) — this part is the reasoning layer,
not a list of facts. It tells Claude HOW to think about a video idea,
using the other parts as evidence: ALGORITHM (what Instagram rewards
right now) + PSYCHOLOGY (viewer state, curiosity, pleasure) + PAIN POINT
(what the avatar needs) + PROVEN STRUCTURE (from the viral-structure
library) + WHAT'S VIRAL NOW.
**Rule:** no step is skipped, no step is guessed. If a step has no
evidence, the master says so in OPEN QUESTIONS and does not invent it.
The output of this reasoning is a RECOMMENDATION (EDIT-ROUTER.md §6):
style pick + three grounds + build plan + QC gates + brand-DNA checklist
+ HUMAN-MADE CHECK. Do not render until the pick is approved.

## The reasoning flow (7 steps, in order)

### Step 1 — Name the avatar's state (PSYCHOLOGY first, not the topic)
Ask: who is watching, and what are they feeling in the 3 seconds before
they see this video? Q's avatar: a creator under 10K, posting for free,
month 4, worked hard, no deal yet — tired, skeptical of gurus, hungry
for proof that someone like them got paid. The video must meet THAT
state, not a generic "creator". If the avatar's state is wrong, every
later step is wrong.
- **Evidence:** audience-psychology-following-growth.md (identity,
  inside language, shared story); pain-point-solution-bank.md P9/P10.

### Step 2 — Pick ONE pain (PAIN POINT)
One pain per video, from the bank, ranked by frequency × intensity.
Never two pains in one hook — the second pain dilutes the first and the
viewer remembers neither. Name the pain in the avatar's own words (the
bank carries the exact wording).
- **Evidence:** pain-point-solution-bank.md (P1–P20).

### Step 3 — Check the algorithm (ALGORITHM)
Ask three questions: (a) Which surface is this for — Reels, Feed
carousel, Stories? (b) What does that surface reward right now — for
Reels: watch time, likes per reach, sends per reach (Mosseri, Jan 2025);
for Explore/carousels: likes, saves, shares. (c) What is the eligibility
gate — original content only (Apr 30, 2026), ≤3 min for Reels
recommendation, no AI-person-without-label. Then translate the signals
into edit decisions: watch time → hook ≤2s + visual event ≤2s; sends →
one sendable line; comments → keyword CTA with a live flow.
- **Evidence:** algorithm-mastery-instagram.md (A1–A11). Never cite a
  weight, a multiple, or a threshold — Meta publishes none.

### Step 4 — Pick the proven structure (STRUCTURE)
Match the pain + the proof available to a structure in the library. The
structure is chosen by WHAT PROOF EXISTS, not by preference: proof-led
needs a real receipt on screen; objection-first needs a real doubt the
avatar actually holds; scale-proof needs a real number. If the proof does
not exist, the video is NOT ready — source it first, never ship the
claim bare (Imagery Agent rule).
- **Evidence:** viral-structure-library.md (S1–S15).

### Step 5 — Design the hook (DESIRE, not info)
Run the Desire Hook test (kallaway): does the hook name a desired
OUTCOME the avatar secretly wants, tied to a relatable CHARACTER — or
does it tease secret information? An info hook ("here are the three best
algorithm hacks") gets views from people who never buy. A desire hook
("here's how to go from 200 to 20,000 followers in six weeks") leans the
buyer in. Then run the hookscore gate (5 checks, STRONG ≥70 — kill bad
hooks). Then check the "how I" question: for HOOKS, first-person "how I"
is the measured winner (Shannon McKinstrie — one hook edit, +30,000
followers); for the PAYOFF, second-person "you" is the house rule. Hook
in "I", payoff in "you".
- **Evidence:** hooks-jev-hook-bank.md; hooks-hookscore-kill-gate.md;
  viral-structure-library.md S8.

### Step 6 — Place the proof (SHOW IT)
Every claim gets its proof object on screen AT the claim second — real
screen, real number, real creator, never a flat plate pretending to be
proof. Proof full-screen in the first 2 seconds for proof-led (P-pack
blur spec on hidden-method proofs; RC creator media as-is with @handle
visible, never framed as members/endorsers). Q's face is present during
the hook — PiP or split, never a faceless board open. One proof object
per claim; if a claim has no proof object, cut the claim.
- **Evidence:** parts/imagery/; EDIT-ROUTER.md §7 (proof-at-the-claim-
  second); MEMORY.md blur law.

### Step 7 — Choose the CTA + conversion path (SALES)
One action, one sentence: Comment KEYWORD (flow must exist BEFORE the
post — ENGINE Step-0 gate) + the dual-CTA profile line (never the literal
phrase "link in bio"). Conversion path: value → WAITLIST capture (email
in DM + waitlist_dec7 tag) → Dec 7 join link in DM → Dec 13 close.
Urgency is always a real deadline. A no is a no.
- **Evidence:** parts/sales-closing/; parts/gap-fills/gap-funnel-manychat.md.

## The check before the build (the master asks itself)
1. **Is the pain real?** (bank entry + source — yes/no)
2. **Is the proof real?** (object on disk — yes/no; if no, STOP)
3. **Is the hook a desire hook?** (outcome + character — yes/no)
4. **Is the structure proven?** (library row + engagement — yes/no)
5. **Does the algorithm reward this shape on this surface?** (A1–A11 —
   yes/no)
6. **Is the keyword flow live?** (ManyChat — yes/no; if no, STOP)
7. **Does it still read as Q?** (brand DNA + human-made check — yes/no)
Any NO stops the build until fixed. A build that passes all seven is
ready for the pilot gate (judge one pilot before the batch).

## Failure modes (how the reasoning goes wrong)
- **Info-hook trap:** the video teaches instead of promising. Symptom:
  hook names a topic ("3 algorithm hacks"), not an outcome. Fix: S8.
- **Proof-bare claim:** a number with no screen. Symptom: the viewer is
  asked to believe, not shown. Fix: cut the claim or source the proof.
- **Two-pain hook:** two problems in the first line. Symptom: the viewer
  remembers neither. Fix: pick one pain, cut the other to its own video.
- **Cold-format copy:** lifting a structure whose evidence is cold
  (kingketo tutorial carousel, Oct 28 → Nov 6 collapse). Symptom: "but
  it worked for them" with stale numbers. Fix: check the refresh date.
- **Funnel-post judged as reach post:** a keyword video with comments >
  likes called a failure for low likes. Symptom: wrong metric. Fix:
  judge funnel posts on DM captures (algorithm-mastery H1).
- **Myth as strategy:** building on "sends are 3–5× a like" or "likes
  are dead". Symptom: a multiple in the brief. Fix: algorithm-mastery
  §3 — strike the myth, rebuild on the official three signals.

## Worked example — RC1: "Three deals at 500 followers" (reasoned through)

**The idea:** a proof-led video about @nathanmthomas — 500 followers, 3
brand deals, $1,900 in one week. Posted Nov 8, 2026 ~11:45 AM CT (post
17959768191255295, reel DffVAPDj-P6); thumbnail hook "500 FOLLOWERS /
$1,900 IN ONE WEEK"; COMMENT WAITLIST; caption 388 chars. (MEMORY.md.)

**Step 1 — avatar's state:** a creator at ~500 followers who believes
deals need 10K. They have been told "grow first, earn later" and they
are tired of it. The feeling is disbelief + hunger: "if he did it at
500, what's my excuse?"

**Step 2 — pain:** P10 (posting for free with nothing to show) crossed
with P5 (pitches ignored). The avatar's words: "I'm posting and nobody's
paying me." One pain leads (P10 — nothing to show); P5 is the objection
the Sales specialist answers in the DM, not a second hook.

**Step 3 — algorithm:** surface = Reels. Reward = watch time + sends
per reach + likes per reach (A1). Translation: the hook must be the
numbers in the first 2 seconds (watch time); the sendable line is
"500 followers. $1,900. One week." (a creator forwards that to another
creator with "us"); the keyword WAITLIST drives the comments (H1 —
comments > likes is the funnel signature, not a failure). Eligibility:
original content (Q's own take, real creator's receipts — pass); ≤3 min
(pass).

**Step 4 — structure:** S9 proof-led talking head (home lane) — proof at
0:00, face in the hook. Why S9 and not S5 (objection-first)? Because the
proof is the hook here: the numbers ARE the objection-handler. S5 would
spend 5 seconds on the doubt before showing the proof; S9 shows the
proof in the first 2 seconds and lets the doubt dissolve. The structure
follows the proof, not the preference.

**Step 5 — hook:** desire-hook test. Info-hook version: "Here are three
tips for landing brand deals at 500 followers" — views, low-quality
viewers, never buy. Desire-hook version (shipped): "500 FOLLOWERS /
$1,900 IN ONE WEEK" — outcome (money) + character (a real 500-follower
creator, @nathanmthomas named on screen). Hook in "I"-adjacent framing
("he did it at 500") — the character carries the first person, so Q's
second-person payoff ("you could be making this") stays clean. The
spoken hook says the title words up front (spoken-hook rule), timed to
the words dropping in.

**Step 6 — proof:** @nathanmthomas's receipts on screen at the claim
second; @handle visible, media as-is, never blurred, never framed as a
member/endorser (RC-pack rule — claims attributed to that creator only).
Q's face present during the hook (split/PiP over the proof). Blur law:
RC creator media is NOT hidden-method-app content — no blur applies
except the standing rules.

**Step 7 — CTA + path:** Comment WAITLIST (flow live — ENGINE Step-0
gate passed before posting) + dual-CTA profile line. Path: value (the
proof + the system hint) → WAITLIST capture (email in DM +
waitlist_dec7 tag) → Dec 7 join link in DM → Dec 13 close.

**The 7-checks before build:** pain real (P10 — yes) · proof real
(Nathan's receipts on disk — yes) · desire hook (outcome + character —
yes) · structure proven (S9 — P1 v9/P2/P3 live — yes) · algorithm
rewards this shape (Reels top-3 — yes) · keyword flow live (WAITLIST —
yes) · reads as Q (Sky Form 9/8, PWC skin, face clear — yes). Build
approved → pilot → posted Nov 8, verified live.

**What would have killed it:** an info hook ("3 tips for small
creators"); the proof arriving at 0:08 instead of 0:00; a faceless board
open; a WAITLIST flow not yet live; or judging it the next morning by
its like count instead of its DM captures.
