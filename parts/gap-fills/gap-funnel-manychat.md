# GAP-FILL — Funnel + ManyChat mechanics [Q didn't ask, mastermind added]

Source: Q's ManyChat sweep (Oct 30, 2026 — every live flow verified: zero
skool.com links, zero "doors are open" claims; every keyword path ends
value → WAITLIST capture) + the ENGINE Step-0 gate. Mark: GAP-FILL.

## The rule
Every video's comment keyword must have a working ManyChat flow BEFORE
it posts. A CTA without a flow is a broken promise.

## The mechanics
- **Keyword → value → waitlist:** the flow delivers its promised value
  FIRST (the PDF, the sheet, the list), then routes to WAITLIST capture
  (email in DM + `waitlist_dec7` tag). Never the reverse.
- **47 live flows** (Oct 30). Posting gate: only 20/90 YAP30 keywords
  have flow copy — the other 70 need flows built + verified before
  posting (Q chose: film first, flows later — the gate still binds at
  post time).
- **Routing (Nov 2–Dec 6):** everything routes to the waitlist. Skool
  is Closed; there is no live join link anywhere. No flow may say doors
  are open.
- **Doors open Dec 7:** join link goes to waitlisters' DMs first, Day 1
  live 12 PM CT. The flows flip to join-routing only on Q's word.
- **Dual CTA in every caption:** the Comment KEYWORD CTA + a bio-link CTA
  phrased to dodge IG's "link in bio" reach penalty (never the literal
  phrase). Current routing is to the waitlist.

## Executable steps
1. Before any post: check the keyword's flow exists, delivers the
   promised item, and ends in WAITLIST capture. Three checks, all must
   pass (queued-posting-integrity skill).
2. New keyword? Build the flow + verify it end-to-end (Kiya end-to-end
   WAITLIST test is still owed: comment WAITLIST → email captured → tag
   → 3-Wins PDF) before the video posts.
3. A flow that promises an item it doesn't deliver is quarantined until
   fixed — the video waits.

## Worked example

PWC. WAITLIST flow: comment WAITLIST → email captured → tag →
