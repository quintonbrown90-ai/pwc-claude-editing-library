# GAP-FILL — Render / export + versioning discipline [Q didn't ask, mastermind added]

Source: Q's rules + AGENTS.md lessons (Nov 8 "always post the NEWEST
version"; Oct 12–14 staging failures). Mark: GAP-FILL.

## The rule
ALWAYS post the NEWEST version of a video (latest stack copy by date),
never an older re-encode. A re-encode is never the master.

## Naming
`<TITLE>_v<N>_<date>.mp4` — v1, v2, v3… never "final," never "FINAL2."
The stack folder holds ONE current file per video + the cover + the
caption (one-stack rule). Superseded versions move to `archives/`, never
deleted, never posted.

## Masters vs delivery files
- MASTER: the highest-quality export (1080x1920, ProRes or high-bitrate
  H.264, -14 LUFS, faststart). The master never gets posted directly if
  a delivery trim exists — but the delivery file IS the exact exported
  file, never re-compressed after.
- DELIVERY: the exact file handed to chat BEFORE the approval card fires.
  Post the exact file, no re-encode/compression (Q's rule, Nov 7).

## Re-cut without losing the original
1. Copy the master to a new version (vN+1) — never edit the master in place.
2. Log what changed in one plain sentence ("v9: Tile 11 swapped to
   Adley's 2.8M video; pauses removed").
3. QC the new version on the exported file (freeze/transition/ending/
   lip-sync gates) — a re-cut re-opens every gate.

## Worked example
Backyard #1, Nov 8 01:08: the 1 AM post used the OLD Nov 6 boosted file
(clips at +0.56 dBTP). Q flagged it; the old repost was archived and the
NEWEST Nov 7 15:00 stack copy posted (54.27s, -14.07 LUFS). The rule was
written because the mistake happened once.
