## The rule
"Before you see anything, Claude runs quality control on your scripts, hooks, ideas, so then everything that you get back is already vetted." Three properties:
1. **Runs on three inputs:** scripts AND hooks AND ideas — not scripts only. A bad idea never becomes a script; a bad hook never gets a script written under it.
2. **Runs BEFORE the user sees anything.** The user (Q) sees only vetted output. Unvetted output is reworked or killed inside the gate, never shown "for a quick look".
3. **It is a gate, not a polish pass.** Fail = rewrite or kill, not "fix it later". Same as the hookscore kill-gate: below threshold = do not shoot.

## The numeric threshold — pairs with the 95-gate
Bradford gives no number. The library's numeric threshold is the **95-gate (charliehills)**: score ≥95 to pass. The Quality Gate adopts it: a script/hook/idea scores 0–100; ≥95 passes to Q; below 95 is rewritten or killed. The hookscore kill-gate (parts/hooks/) is the hook-level implementation: STRONG ≥70 / OK ≥50 / below 50 = rewrite, do not shoot. The two thresholds compose: hooks pass their own gate (≥70 STRONG) AND the script passes the 95-gate as a whole.

## The checklist (INFERRED — from the self-check doctrine + Q's standing rules)
Each check is pass/fail. One fail = back for rework; a claim fail = kill the claim, not the script.

## The audit loop — the shipped-post half of the gate (DfKWT3Xkmwz)
The gate checks NEW scripts. The AUDIT checks SHIPPED posts, and feeds the gate:
1. Connect Instagram to Claude (Composio — needs Q's explicit call on connections; flagged, not adopted).
2. Prompt 1: rank every reel by views, shares, saves.
3. Prompt 2: watch the top 5 and bottom 5; break down by length, script, hook — why each worked.
4. "Post more of what works. Stop making what doesn't." Winners feed the Playbook + hook bank; losers retire.
5. "If the data tells you what worked, psychology tells you why it worked." Data first, psychology second — never psychology before data. Same split as the Video Breakdown skill.

## Executable steps
1. Draft the script (Brain + Playbook + brain dump).
2. Run checks 1–6 (Claude self-check). Fail → rework inside the gate; Q sees nothing.
3. Pass 1–6 → human taste pass (check 7). Q line-edits or approves.
4. Only then does the script reach Q as "ready". A script that reaches Q unvetted is a process failure, not a shortcut.
5. After posting: AUDIT loop monthly; feed results back into the Playbook, the hook bank, and the memory folder.
