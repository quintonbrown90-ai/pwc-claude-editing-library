## The rule
Build the effect library as code components, not one-off renders. The `.st-`
pattern: a namespaced CSS component library (tiles, pills, cards, numbers,
subtitles) with named variants. Every device is a named component with a fixed
look, a fixed position, and a trigger — "down to the pixel" is the proof:
showing the code + pixel measurements on screen proves the AI is placing
elements with code, not guessing.

## Executable steps
1. **Namespace:** every component carries the library prefix (`.st-` in the
   source; PWC: `.pwc-`). Tiles, pills, cards, numbers, subtitles — each a
   component, each with named variants (glass / teal / gold / navy — the
   source's red pill variant is DROPPED per Q's NO RED law; red maps to gold).
2. **Component spec:** each component lists its look (colors, font, size),
   its position (safe-zone coordinates), and its trigger (the spoken word /
   line that fires it). The spec is the component; the render is an instance.
3. **Long-form layouts as router entries:** split screen, comparison,
   bullet-pointing, animated framework — each a named layout with a trigger
   ("like this" fires the layout). Same shape as the claw-machine picker.
4. **Pixel proof:** show the placement spec on screen during teaching builds
   (code + pixel measurements) — the credibility device for "AI placed this."
5. **Cost/time anchor:** "$500 and a week" vs AI — the value proposition in
   one line. Q's version: his own editing cost anchor, real numbers only.

## Worked example (PWC)
`.pwc-proof-card`, `.pwc-count-up`, `.pwc-hook-pill`, `.pwc-cta-strip` —
four components, named variants, fixed safe-zone positions, word triggers.
A P1 build lists its components before rendering; the checklist shows each
component placed to the pixel.

## Human-made check
A component ships only when its spec (look + position + trigger) is written
down. An unnamed device is a one-off, not a library entry.
