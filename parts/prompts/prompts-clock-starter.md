## The rule
"It's not you, it's the clock. Your Claude limit works in 5-hour windows, and
a window only starts when you send your first message." So make Claude send
that first message for you at 6 in the morning, while you're asleep — 3 fresh
windows in the workday instead of 2. "One catch. Your weekly limit stays the
same, so this spreads your usage out. It doesn't give you more."

## Executable steps
1. **The window rule:** a 5-hour limit window only starts when you send your
   first message. An early first message = an early window.
2. **The starter:** a tiny scheduled task at 6 AM — type "hi", pick Haiku
   (the smallest model, so it barely touches the limit), set it to daily,
   6 AM. The starter is a ping, not a job.
3. **The honesty line:** the weekly limit stays the same — this spreads usage
   out, it doesn't give you more. State the catch wherever the trick is
   taught; never sell it as extra usage.
4. **Q's version (if adopted):** the 6 AM starter runs on Q's Claude lane so
   the morning batch window opens before Q wakes; the heavy renders run in
   the fresh windows. Only with Q's word.

## Worked example (PWC)
6 AM Haiku "hi" → window 1 opens 6–11 AM (morning batch) → window 2 opens
on first real message after 11 → window 3 in the evening. Three fresh windows
instead of two — same weekly limit, spread out.

## Human-made check
The starter's only job is the ping. If it ever does real work, it's not a
starter anymore — it's a job, and it costs the window.
