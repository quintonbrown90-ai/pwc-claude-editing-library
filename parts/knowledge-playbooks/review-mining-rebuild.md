## The rule
"Every paid app has a list of complaints. It's sitting right there in the reviews." The complaints are the brief. You do not guess what to improve — you read what users already said is broken, and you fix exactly that.

## The mechanic (four moves)
1. **Read the public complaints.** "It actually reads what the users hate in their reviews." The demo app is Parlo (a language app); the reviews on screen (f_024–f_026, VERBATIM-FRAME): "Ran out of hearts in the middle of a lesson" / "An ad after every single lesson" / "Love the parrot, but Super keeps getting pricier" / "Out of hearts? Pay or wait 6 hours". Four complaints, each specific, each quotable.
2. **Turn each complaint into a fix.** The fix list (f_027, VERBATIM-FRAME): "Unlimited hearts / No ads. Ever. / One flat price". One fix per complaint — no more, no less. The fix list is the same length as the complaint list.
3. **Build the version with the fixes in.** "Then fixes what users hate in your version." The rebuilt app is shown side-by-side with the original (f_028–f_030) — same screens, complaints removed.
4. **Test every flow before handoff.** "It even tests every flow for bugs before it hands it back to you" — the TEST RUN checklist (f_019–f_020): Lesson flow / Streak saves / Offline mode / Double tap. The rebuild is not done until the checklist passes.
